FILES: src/pm/blueprint.cljs (new `breaks-build?`/`max-part-dim`), src/pm/core.cljs (new `apply-approved!`, `revert-to-last-good!`, `!last-good`, wired into the blueprint-click handler), resources/estate.edn (added a second, deliberately broken blueprint), test/pm/blueprint_test.cljs (new `breaks-build?` tests).

WHAT: Clicking a pending blueprint's ghost now goes through `pm.core/apply-approved!` instead of approving blindly. It snapshots `!world` as "last good," then checks `pm.blueprint/breaks-build?` (an unknown shape, a malformed size, or a part scaled past 20 m — the kind of thing a runaway generation produces). A safe blueprint is approved as before — `pm.scene`'s existing sync un-ghosts its mesh in place next frame, no page reload. An unsafe one never reaches `!world`: `revert-to-last-good!` resets the atom to the pre-approval snapshot and logs a console warning, so the estate can never be left showing something broken.

HOW TO SEE IT: Run the game and look near the mailbox/canal (east bank) for two ghosted blueprints. Click the bench-by-mailbox ghost — it goes solid immediately, live, no reload. Click the lamp-post-by-canal ghost (its look has an invalid `:pyramid` shape) — approving it has no visible effect because it's reverted instantly; check the browser console for "Prime Meridian: blueprint reverted -- kept the last working build".
