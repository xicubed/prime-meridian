WHAT: `bb events-bridge` runs a websocket server on `127.0.0.1:8092/events`, writing a rotating pairing token to `state/events-bridge.edn` (same pattern as the existing crew bridge). It accepts a connection only when the request's Origin is `http://localhost:8080` *and* the query carries the matching token (`pm.events-bridge/accept?`); anything else gets a plain 403 and is never upgraded to a socket. Once connected, it streams the four bridge events (`pm.events`: agent-event, answer, chore-done, jack-out) from the shipped sample file as JSON frames, and validates/logs anything the client sends back. The game polls for the token, opens a real `js/WebSocket.` to it, decodes incoming JSON back into the EDN event shape (`pm.events-bridge/to-json`/`from-json`), auto-answers an agent's question to demonstrate two-way traffic, and reconnects with exponential backoff if the socket drops.

HOW TO SEE IT: run `bb scripts/events_bridge.clj` alongside the usual `npx shadow-cljs watch app`, then load the game — the HUD line changes from `bridge ws off` to `bridge ws open`, and the trailing `events N/M ok` segment switches from the static demo sample to live counts as the server streams real JSON events over the socket (watch `crew/events-bridge.log` for connect/receive lines). Without the bb server running, the HUD stays on `bridge ws off` and falls back to the demo sample, same as before.
